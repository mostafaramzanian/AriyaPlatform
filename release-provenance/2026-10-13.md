## Release notes

This is the production release candidate validated through the full gate pipeline,
built on the controlled **NestJS 11 → 12 migration**. The migration resolves the
runtime `js-yaml` advisory: `@nestjs/swagger@12.0.2` resolves `js-yaml@5.4.2`
(patched); the vulnerable `5.3.0` path is absent from source, lockfile, image and
audit. NestJS 12 packages are ESM-only; the runtime image and CI target Node 24.

## Security and risk status

- **npm audit (lockfile `EFCF28BC…`):** **31 findings — 5 High, 26 Moderate,
  0 Critical.** This is an honest count, not a claim of zero vulnerabilities.
- **R2 RESOLVED:** runtime `js-yaml` = 5.4.2 (removed, not accepted).
- Remaining findings carry documented **limited risk acceptances** (R1 braces
  dev-only; R3 js-yaml 3.15.2/sprintf-js dev-only; R4 decode-uri-component via
  minio; R5 fast-xml-parser via minio; R6 uuid via exceljs), each with conditions
  and review triggers. A MinIO major-version migration program is the standing
  remediation path for the minio-chain findings.
- **ADR-0006 limitation:** RS256 access tokens remain valid until their TTL;
  revocation is ttl-bound (300s) — immediate access-token revocation is not
  claimed. Refresh/session revocation remains authoritative.
- **Deployment security (publish-side hardening in `docker-compose.yml`):**
  MinIO and JWT credentials are loaded from Docker secrets under `./secrets/`
  (gitignored) via `/run/secrets/` — no `minioadmin` default, no JWT placeholder,
  fail-closed without the files; `JWT_LEGACY_HS256_ENABLED` is explicitly `false`.
- **Secret-scan note:** the tree carries 39 scanner findings that are all
  documented fixtures — a PEM skeleton in `.env.example` comments, test-suite
  passwords, documentation example tokens, and a variable literally named
  `secret`. No real credential, token, key, backup, dump or runtime image is
  committed.
